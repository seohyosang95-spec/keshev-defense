## 2. 핵심 기능 3가지 시연 순서

### 1) 기록 보기

1. 케셰브를 실행하고 `보호 현황`을 엽니다.
2. 기록 목록·상태·상세와 현재 조회 범위를 보여 줍니다.
3. 기록이 실제 운영 연결에서 온 것인지, 확인 불가·미연결인지 설명합니다.

- 제공된 부분: 제공 화면이 전달한 기록 목록·상세·상태를 표시하는 기본 경계와 필터.
- 내가 직접 개선한 부분: 핵심 기능 우선순위 요약, 조회 범위와 확인 불가 상태를 구분하는 안내.
- 실제 확인 결과: 기록 화면 구조와 상태 처리는 확인했습니다. 현재 기본 실행의 운영 계정·SDP 연결은 `disconnected`이므로 실제 XDR·운영 기록이 연결됐다고 말하지 않습니다.
- 근거: `student/extension.mjs`, 기본 실행의 `/api/events` 연결 상태, 화면의 미연결·확인 불가 안내.

### 2) 내 PC 상태

1. `내 PC 상태`에서 CPU·메모리·디스크 카드를 보여 줍니다.
2. 각 값의 단위·측정 시각·조회 근거를 확인합니다.
3. `내 PC 다시 측정`을 눌러 값과 시각이 갱신되는지 보여 줍니다.

- 제공된 부분: 앱 화면에 학생 영역을 표시하는 공통 경계.
- 내가 직접 개선한 부분: 로컬 OS 실측 API, 측정 시각·근거·직전 측정 대비, 로딩·실패·다음 행동 안내.
- 실제 확인 결과: 2026-10-26 11:29:58 KST 기준 CPU `6.3%`, 메모리 `42%`, 앱 설치 드라이브 디스크 여유 `69.5%`가 `local-os` 근거와 함께 반환됐습니다. 값은 시연 시점에 달라지는 실제 측정값입니다.
- 근거: `GET /api/system-metrics` HTTP 200, 응답의 `status: measured`, `source: local-os`, `measuredAt`.

### 3) 위험 알림

1. 학생 영역의 위험 알림 요약을 보여 줍니다.
2. 알림이 있으면 위험도와 다음 확인 단계를 읽습니다.
3. 알림이 없거나 운영 연결이 없으면 그 범위를 한정해 설명합니다.

- 제공된 부분: 제공된 상태·알림 입력을 화면에 전달하는 기본 영역.
- 내가 직접 개선한 부분: 기록·내 PC 상태·위험 알림의 우선순위 카드, 위험 상태와 확인 필요 상태의 구분, 다음 행동 문구.
- 실제 확인 결과: 알림 UI와 상태 분기 코드는 확인했습니다. 현재 운영 연결이 `disconnected`이므로 실제 침해·공격 탐지 결과가 있다고 주장하지 않습니다.
- 근거: `student/extension.mjs`의 `renderFeatureSummary`·위험 알림 렌더링, 현재 실행의 연결 상태.

## 4. 포장 결과와 다시 만드는 방법

### 포장 명령

```powershell
npm run check
npm run package-app
npm run build-installer
```

현재 제공된 `package-app`은 `--source`, `--out`, `--finish-materials` 옵션을 받는 새 도구가 아니라 기존 `npm run package-app` 명령입니다. 별도 포장 스크립트는 만들지 않았습니다.

### 실제 결과

- 실행 묶음: `dist/keshev-package`
- manifest: `dist/keshev-package/APP_PACKAGE_MANIFEST.json`
- 설치 안내: `dist/keshev-package/INSTALL.md`
- manifest 포함 파일: 68개 (이 최종 시연 기록을 포장본에 포함한 뒤)
- 실행 진입점: `launch-keshev.ps1`
- 선언된 실행 환경: Node.js `24.19.0`
- 설치 프로그램: `dist/installer/KeshevSetup-0.2.11.exe`
- 설치 프로그램 SHA-256: 빌드 때 생성되는 `dist/installer/INSTALLER-GUIDE.md`와 `dist/installer/KeshevSetup-0.2.11.sha256.txt`에서 확인

`APP_PACKAGE_MANIFEST.json`에는 `source.git.head` 필드가 없습니다. 따라서 manifest만으로 커밋 동일성을 증명하지 않습니다. 앱 기능 코드는 `1f3a725`에 있고, 이후 문서만 추가한 커밋에서 깨끗한 작업 폴더를 확인한 뒤 같은 소스 트리로 포장했습니다.

### 실행 확인

1. `dist/keshev-package`의 `tools/start-alekov.ps1`을 승인된 실행 환경에서 포트 `5198`로 실행했습니다.
2. `/`, `/api/system-metrics`, `/api/local-observation`, `/student/extension.mjs`가 모두 HTTP 200이었습니다.
3. 학생 모듈 응답에 「막혔을 때」 안내가 포함된 것을 확인했습니다.
4. 테스트 Node 프로세스는 확인 뒤 종료했습니다.

설치 프로그램은 사용자 단위로 설치되며, 실행에 필요한 Node.js는 받는 PC에 별도로 준비해야 합니다. Node.js를 setup.exe에 포함했다고 적지 않습니다.

## 5. 확인하지 않았거나 남은 한계

- 실제 운영 계정·SDP 연결과 실제 XDR 기록 수신은 확인하지 않았습니다.
- 위험 알림은 현재 전달된 조회 범위에 근거하며, 침투·공격 시험이나 침해 판정을 수행하지 않습니다.
- Windows 이벤트 경고·오류 건수는 기록 통계일 뿐 보안 사고 판정이 아닙니다.
- 방화벽은 읽기만 하며, 정책의 일부가 권한·정책 때문에 `확인 불가`일 수 있습니다.
- 다른 Windows 사용자 계정이 처음부터 안내만 보고 설치한 관찰은 실시하지 않았습니다. 별도 경로·설치본 실행은 직접 확인했습니다.
- 코드 서명·Microsoft Store·winget 등록은 하지 않았습니다. 설치 PC의 보안 정책에 따라 경고가 나타날 수 있습니다.

## 6. 독자 디자인 원칙

- 외부 코드·그림·폰트·라이브러리를 가져오지 않고 기존 학생 영역에 직접 작성했습니다.
- 첫 화면은 `LOCAL OBSERVATION / READ ONLY` 배너로 앱의 범위와 읽기 전용 원칙을 먼저 알립니다.
- 핵심 기능 3개는 숫자 카드로, CPU·메모리·디스크는 실측 카드로, 연결·기록은 별도 보라색 영역으로 구분했습니다.
- 색상은 정상·주의·확인 불가의 의미를 유지하고, 모든 상호작용 요소는 키보드 포커스가 보이도록 했습니다.

## 7. 시연자가 말할 핵심 문장

> 케셰브는 제공된 기록·연결 화면과 제가 추가한 로컬 PC 실측·연결 기록·실행 안내를 한 화면에서 구분해 보여 줍니다. 실제로 읽은 값은 측정 시각과 근거를 함께 표시하고, 운영 연결이 없는 부분은 확인된 것처럼 말하지 않습니다.
